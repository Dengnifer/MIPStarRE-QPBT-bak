## Review

F1 remains merge-blocking. Acquisition creates the lock directory before writing its owner files, while CI and housekeeping delete ownerless or apparently stale locks. Their stale-check/delete sequence is also subject to replacement races, and releases do not verify an ownership token. Two processes can consequently publish packages or build concurrently despite the single-writer invariant.

F2’s original top-level symlink case is guarded, but containment is still incomplete. `worktree-setup.sh` follows package-level links during its duplicated ProofWidgets cleanup. The warmer also accepts deeper links such as `proofwidgets/.lake` or `.git/index`, then dereferences them during `mkdir` or `chmod`; the pending marker is opened with truncation without a no-follow check.

F3 freezes the fetched tree before proving that it is build-complete. Mathlib describes `cache get` as downloading “as many ready-made olean files as possible,” not as guaranteeing every artifact exists ([official Mathlib guide](https://github.com/leanprover-community/mathlib4/wiki/Lean-4-survival-guide-for-Lean-3-users)). A cache miss therefore leaves the later build unable to populate the now read-only dependency tree, with no repair path for that key.

For F4, `keyhash` is computed before `--packages-only` invokes Lake. If dependency resolution changes `lake-manifest.json`, package publication uses the new package key while tier 1 is stamped and published under the old key. The key must be computed or revalidated after package preparation.

For F5, failed post-build package validation sets the snapshot to `partial`, but publication still proceeds. Partial publication is appropriate for a compiler failure under valid dependencies, not for a failed dependency-boundary check.

F6-F9 remain from the prior ledger: there is no migration implementation for legacy private trees; signal cleanup can exit zero; abandoned `.incoming.<pid>` trees are neither recovered nor collected; and cross-volume worktree/cache layouts permanently fail with `EXDEV`.

F10-F11 leave housekeeping outside the new ownership model. It can preserve another private 7.3 GB tree, invokes Lake without the prescribed Git-environment wrapper, and suppresses both pre-build and post-build validation failures. CI similarly preserves private trees instead of migrating them through the canonical package preparer.

Prior findings now resolved are exact stale-link validation, CI target validation, portable hash computation, atomic same-filesystem final publication, basic cache-warmer integration, early return after package-preparation failure, isolated test locking, the trusted-primary setup path, and the EVOLUTION Trigger/Change structure. The focused test still does not exercise lock stealing, nested symlinks, signals, crash recovery, `EXDEV`, incomplete caches, or the warmer’s key/validation ordering.

The exact-head local CI was reported green. Read-only checks also passed `git diff --check`, shell syntax validation, ShellCheck, and Python parsing; no state-mutating tests were rerun in this review session.
