## Review
F1: Check selection verifies only `name`, app slug, head SHA, and repository URL. It never resolves the Actions run to confirm its workflow path is `.github/workflows/comparator.yml`. The source scan is also bypassable: `run: ./verify.sh` may belong to another job, while the required `verify.sh` strings may occur in comments or unreachable code after `exit 0`. A no-op `comparator` job can therefore green-light review without running NanoDa. Bind the check to the actual workflow run/job and add decoy-job and dead-code tests.

F2: The companion checkout becomes `WORKTREE`, and `dispatch.sh` both launches Codex with `-C "$WORKTREE"` and instructs it to read `AGENTS.md` and `local/protocols/*.md` there. A companion PR can therefore edit instructions given to its own reviewer, contrary to `local/protocols/review.md` §3. The dry-run test verifies copied persona files only; it never exercises dispatch with a malicious companion `AGENTS.md`. Keep the instruction root trusted and expose the companion tree strictly as review data.

Shell syntax, Python AST parsing, and `git diff --check` passed. Targeted unit tests could not be rerun in this read-only sandbox because no writable temporary directory was available.

VERDICT: CHANGES_REQUESTED
