## Review

Prior F1-F4 are resolved: package links are checked against the derived key, CI validates them before and after building, atomic final publication prevents directory nesting, and hashing now uses the portable validated helper. F5 is only partially resolved: the old cache warmer necessarily created a populated private tree, which the new path refuses without providing a migration command or documented procedure.

For F6, a failed publication retains the private tree and retry marker. On retry, the ProofWidgets workaround follows top-level package symlinks before publication rejects them; it may run `git reset --hard` through `pkg/.git` or create directories through a symlink named `proofwidgets`.

For F7, `warm-worktree.sh` creates the lock directory before writing ownership metadata. CI treats an ownerless lock as immediately stale, while housekeeping deletes any ownerless lock. The stale-lock rename also has an ABA window, and releases do not verify ownership. These paths can concurrently enter the protected section, violating the machine-wide build invariant.

F8-F11 are publication-boundary failures. Signal cleanup preserves an unrelated successful `$?`; untrappable termination strands a complete incoming tree; `os.rename` cannot cross filesystems despite configurable cache/worktree locations; and a failed fetch still proceeds into the potentially hours-long cold build.

F12 should explicitly place `MIPSTARRE_FULL_BUILD_LOCK` under the temporary test root. F13 should direct worktree users to the primary checkout’s setup script and pass the target worktree explicitly.

F14 violates the normative amendment procedure in `local/protocols/meta.md:35-43`: it neither cites an incident, telemetry observation, or user decision nor records a distinct file-level Change description.

The exact-head CI supplied to this review is green. `bash -n` and `git diff --check` pass. The focused unittest could not be rerun in this read-only sandbox because no writable temporary directory was available.
